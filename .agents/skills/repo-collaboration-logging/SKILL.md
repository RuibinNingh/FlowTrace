# 仓库协作与日志设计

将 OMRS 的设计方法适配到目标仓库，使维护者能够快速找到当前事实、接续任务，并核实变更与验证。此包包含设计说明和模板，不含原仓库门禁脚本或日志实现。

## 按需读取

| 当前任务 | 阅读材料 |
|---|---|
| 设计 AGENTS.md、文档入口、职责分工或计划接力 | [协作与文档设计](references/collaboration-design.md) |
| 设计任务日志、历史保护、索引或文档门禁 | [维护任务日志](references/task-logging.md) |
| 设计运行日志、调用记录、轮换或日志导出 | [运行日志设计](references/runtime-logging.md) |

只读与当前任务相关的材料。维护任务日志与程序运行日志承担不同职责，不因为迁移其中一种就自动改造另一种。

## 迁移方法

1. 明确用户要设计、模板、打包还是实际落地。只要求提取或打包时，在仓库外生成交付物，不安装技能或修改源仓库。
2. 检查目标仓库现有规则、文档、代码、测试与实际执行能力；有 Git 时先确认已有改动。复用既有目录和工具，不预设目标项目拥有 OMRS 的环境。
3. 给出简短适配清单：保留哪些机制、替换哪些路径与命令、哪些能力缺失。用户已要求落地时，在授权范围内接着完成，不把清单当作等待再次确认的关卡。
4. 小项目先建立规则入口、相关模块文档与任务留痕；有跨轮接力需求再拆计划文件。运行日志按自身持久性、并发和容量需求设计，不强制引入数据库或新服务。
5. 按实际改动验证并交付。分别说明已执行、未执行及原因；文档结构合格不能证明命令已执行或业务行为正确。

## 可复用模板

起草相应文件时再读取模板。所有 `{{…}}` 都是迁移时替换的字段，不能原样当作已完成内容；不需要的章节应删去。

- [AGENTS.md 模板](assets/templates/AGENTS.md)：共用规则、按需阅读与代码到文档映射。
- [任务日志模板](assets/templates/task-log.md)：任务块及五节证据结构。
- [模块文档模板](assets/templates/module-doc.md)：速查头与当前契约。
- [计划模板](assets/templates/plan.md)、[进度模板](assets/templates/progress.md)：跨轮任务的意图、范围与恢复入口。

## 迁移边界

- 保留目标项目已有有效约定，合并相关规则；不要整文件覆盖已有 AGENTS.md，也不要为套模板重写历史日志。
- 当前代码、测试和配置提供现状证据；用户目标决定要达到什么状态。发现二者不一致时，写清差异，不能把现状误当成已满足需求。
- 能力与权限分开判断：能够运行命令不代表得到生产操作授权；技能不授予提交、推送或部署权限。已有用户授权继续有效，不重复申请。
- 目录、维护者名称、语言、时区、篇幅阈值、容量和门禁命令都应适配目标项目。不得将 OMRS 的本地约定提升为无条件要求。

## 来源

设计提取于 OMRS 的 `AGENTS.md`、`AI/README.md`、`AI/plans/README.md`、日志相关模块文档，以及 `omrs/log_utils.py`、`omrs/feedback.py`、`omrs/log_export.py`、`omrs/runtime_records.py` 和相关测试，提取日期为 2026-10-21。这些路径仅作来源说明，使用本技能不依赖 OMRS 源码。包内不包含真实日志、业务数据或凭据。
