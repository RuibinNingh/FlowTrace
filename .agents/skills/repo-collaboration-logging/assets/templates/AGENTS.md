# {{项目名称}} 仓库协作准则

## 开始任务前

- 从 `{{文档入口}}` 按任务找相关模块，先读速查头，再按需深入。
- 有进行中计划时，先读 `{{计划目录}}/主题/progress.md` 的状态与下一步，再读对应执行说明和计划章节。
- 有 Git 时先运行 `git status --short`，保留已有修改；无 Git 时说明可用基线，必要时在临时副本建立补丁基线。
- 当前代码、测试与配置提供现状证据，历史解释意图；相关文档过时就在本任务同步，未实现目标不能写成现有能力。

## 执行能力与范围

按实际工具、数据和环境定义能力，不凭维护者名称推断权限。规划任务只产出计划；执行任务按约定范围实现和验证。缺少材料或工具时记录限制，不补造事实。

保护用户已有修改，只处理本任务范围。测试使用隔离数据与独立端口，移除会控制生产服务的环境配置。提交、推送和生产操作按用户已有授权范围执行；能力可用不等于已授权。

## 计划与用户意图

保留用户原话，每个主线步骤对应明确需求；额外改进单列为可选。计划写明目标、范围、默认决策、验收、执行者与停止条件。分期控制风险，不自动缩短交付范围；按既定推荐连续完成，不在每期结束重复询问。

实现偏差记录在任务日志。需要改变目标或范围时显式登记；遇到停止条件、必需信息缺失或未授权外部操作时说明阻碍。跨轮任务更新进度，写清当前基线、停在哪一步及下一动作。

## 文档与留痕

模块文档只写当前行为，标题后提供职责、入口、不变量、必跑测试和相关材料五行速查。规则、映射、索引和已知缺陷各有单一权威位置；派生索引由工具生成。

仓库有持久化改动时，在 `{{任务日志目录}}` 新建或续写本次任务日志。使用任务状态块与背景、行为变化、影响文件、已执行验证、未执行验证五节。进行中同任务可续写；交付后历史保留原文，只追加带实际日期和依据的勘误。新任务另建记录，不以修改历史代替本次留痕。

只读答疑或仅生成仓库外交付物不制造仓库空日志。私人日志不进入公开索引；模块文档不依赖接收者拿不到的材料。

## 交付前

1. 复核本任务实际差异与受影响文档，保护无关修改。
2. 完成风险相称的验证；页面变更走隔离服务与真实浏览器主路径。
3. 补齐真实任务证据与计划进度，运行 `{{已有文档检查命令及基线参数}}`；没有检查器时明确采用人工核对，不声称已通过自动门禁。
4. 报告完成内容、实际验证、未验证及原因、遗留问题和下一步。区分本地完成、提交、推送与部署状态。
