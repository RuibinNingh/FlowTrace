# 协作与文档设计

## 将常驻规则与按需知识分开

AGENTS.md 每次进入仓库都可能被读取，适合保存共用底线、查找入口、交付要求和代码到文档的映射。模块机制、详细规划流程和环境命令放入按需文档，减少上下文负担，也避免同一规则在多处修改。

下面是 OMRS 信息分层的可移植结构。路径是示例；目标项目已有 `docs/` 等结构时直接沿用。

| 载体示例 | 回答的问题 | 不承担的职责 |
|---|---|---|
| `AGENTS.md` | 怎么协作、改什么要同步哪些文档 | 全部模块细节与历史 |
| 根 `README.md` | 用户怎样安装、启动与使用 | 重复完整 API 与版本历史 |
| `AI/README.md` | 当前任务该读哪份文档 | 再复制一份协作规则 |
| 模块文档 | 当前行为、入口、不变量、验证方式 | 混写未实施方案或任务流水 |
| `plans/主题/plan.md` | 用户目标、范围、验收与停止条件 | 每轮命令回执 |
| `plans/主题/progress.md` | 做到哪、下一步、中断后如何恢复 | 复制全部任务日志 |
| 任务日志 | 这次为什么改、改了什么、实际怎么验证 | 替代模块文档描述当前全貌 |
| 版本变更记录 | 版本级的用户可见变化 | 完整任务证据 |

一个项目不必一次拥有所有载体。按信息量拆分，确保每类信息有明确的权威位置。

## 阅读顺序服务于接力

从文档入口按任务定位模块，不要求先通读整个知识库。属于进行中计划时，先读进度状态块与下一步，再读对应执行说明及计划章节。进度应该能回答当前基线、完成位置、未验证事项和下一项具体动作。

模块文档标题后提供五行速查：职责、入口、不变量、必跑测试、相关材料。它使维护者在读长文前判断相关性。OMRS 用前 15 行、单段约 800 字和单文件约 40KB 控制阅读成本；迁移时按目标项目规模选择阈值，不需要照搬数字。

## 按实际能力定义模式

把“谁负责”与“在哪里、能做什么”分开记录。规划者维护目标和验收，执行者按契约实现，发布者处理外部状态；一个维护者也可以兼任这些职责，不要求引入多个代理。

执行环境可能只有源码快照，也可能具有 Git、依赖、隔离服务与网络。先验证能力；缺失文件或依赖明确记录，不假定另一环境的测试已完成。规划模式只产出计划；执行模式才修改业务实现。不要仅凭模型或客户端名称推断权限。

源码快照没有 Git 时，可在获准使用的临时副本建立基线，以补丁表达变化。交付要包含基线身份、应用方式和接收方补验步骤。不要把测试替身、个人配置或缺失材料的猜测混入交付物。

## 以用户原话约束计划

计划先保留用户原话，再写可验证的完成状态。每个主线工作项都要能对应一条需求；额外想做的事情单列为可选，不让它挤占主诉求。

跨阶段拆分控制风险和回滚粒度，不自动缩短交付范围。先完成用户能看到的主路径，文档门禁和索引等收尾仍需完成。执行说明写明执行者、能力要求、默认决策、验收和停止条件；实现偏差记录在任务证据中，目标或范围的变化显式登记，不能悄悄重写计划。

常规实现选择采用既定推荐并继续。遇到明确停止条件、影响范围的事实差异、缺少必需信息或未授权外部操作时，说明阻碍；不要在阶段结束时反复询问是否继续。

## 当前事实与历史各有位置

现状判断以当前工作区代码、测试和配置为依据，Git 历史解释设计意图，模块文档负责整理当前契约。发现文档过时，在相关任务内同步；未实现目标明确标为计划，不能写成当前能力。

模块文档只写现在；任务日志保留这次的事实，版本记录保留版本变化。已交付历史的修改规则见[维护任务日志](task-logging.md)。已知缺陷集中登记一次，其余位置引用，避免三份待办逐渐分叉。

若源码包不包含私人日志，模块文档就不能依赖这些日志才能理解当前行为。将仍有用的经验提炼为可随源码导出的规则或设计说明。

## 让变更映射可检查

在一个权威位置维护“代码范围 → 必更文档 → 条件附加项”。一条映射列出多份必更文档时应全部核对，不能更新其中一份就判定同步完成。条件项按接口、存储或权限等实际变化判断。

映射最好使用明确列，避免让脚本从复杂自然语言猜测。迁移已有表格时保留路径中的空格，识别删除和改名；删除一份文档不能算作已同步。文档检查器也不能判断内容是否真实，事实仍需人工核对与业务验证。

生成的索引、路由表从事实来源自动生成，不手工维护第二份。任务索引只收纳项目允许公开或提交的文件，不将被忽略的私人日志带入版本库。

## 交付验证与实际风险对应

开始时确认已有改动并保留；结束时复核本任务差异。测试使用隔离数据和独立端口，清理会指向生产重启的环境变量或控制入口。生产发布与本地实现分开记录，已有授权按范围执行。

页面行为变更需要启动隔离服务并走真实浏览器主路径；单元测试只能证明它覆盖的层。交付报告明确实际运行了什么、什么没运行以及原因，不能把预期计数写成实测结果。
