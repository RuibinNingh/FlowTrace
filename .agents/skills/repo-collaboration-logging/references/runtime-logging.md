# 运行日志设计

## 先区分事实存储与辅助留痕

| 记录类型 | 回答的问题 | 持久性与用途 |
|---|---|---|
| 业务事实与正式回执 | 业务到底有没有提交、重试是否复用 | 使用领域事务和回执；恢复与幂等依据 |
| 调用生命周期记录 | 一次工具调用开始、结束或中断了吗 | 保存有界摘要；不能独自证明领域变更已提交 |
| 运行诊断与调试日志 | 执行过什么路径、哪里需要排查 | 辅助诊断，可按策略轮换；不用于重放业务 |
| 维护任务日志 | 维护者为什么改、怎么验证 | 人工任务证据；见[维护任务日志](task-logging.md) |

先判断目标记录能否丢失。业务要求持久必达的记录属于事务契约，不能套用辅助诊断的尽力写入策略。下面的故障隔离主要适用于辅助记录。

## 成功记录必须对应正确时机

OMRS 的反馈在业务事务成功后追加诊断，避免写出随后回滚的“成功”。迁移时可在事务内收集待记事件，提交后再输出；回滚、无效条目与幂等复用不重复追加成功诊断。

用稳定实体编号、调用编号和提交编号关联记录，显示名称与路径只作补充。不要依赖自由文本、当前名称或当前映射推断旧业务身份。

业务已提交而诊断失败时，保留业务成功结果；发出有界、可观察的故障信号，避免调用者因误判失败而重复提交。这种后置尽力写入可能在进程崩溃窗口丢记录，不提供崩溃时恰好一次保证。若用户确需持久交付，应另行设计事务事件等机制，不能仅靠移动日志调用达成。

## 结构化与内容边界

按查询用途选择字段，例如带时区时间戳、事件类型、稳定实体编号、调用或提交编号、结果码与有限计数。时间表示业务日期还是实际记录时间要写清；耗时使用单调时钟。只有在目标项目有需要时才增加字段。

对调用摘要使用字段白名单；正文、密钥、请求头、图片字节、下载地址和原始异常不要默认进入摘要。错误码映射到固定安全说明。字符串长度、集合数量和单条字节数分别设界限。

AI 原始请求／响应属于另一种高敏调试数据，默认关闭、显式开启，并说明保存范围。即使保存有界原文，也不能宣称已经自动脱敏。超大单条 JSON 记录应改写为仍合法的省略说明，例如 `truncated: true` 与 `original_bytes`，不要从中间截断而破坏 JSONL。

## 调用生命周期保留不确定性

有调用历史需求时，可记录 `running → success / failure / interrupted`，终态不随普通读取反复变化。启动恢复时将遗留进行中记录标为中断，不推测其业务结果；结束时间未知的细节不要补造。

批准、执行中和已提交是不同状态。辅助历史写回失败后，依据领域正式回执修复关联状态；读取详情本身不能触发重做业务。没有可核验回执的中断，提示先核对目标当前状态再决定重试。

此设计不要求所有项目新建运行数据库。已有结构化日志、追踪系统或调用存储能满足查询和恢复需求时直接复用。

## 写入、轮换与清理共享边界

对受管日志使用短期打开的文件句柄，将追加、轮换和清理放在同一串行化边界内。多进程写入不能只靠线程锁；锁等待有界，适配目标操作系统。按完整记录轮换，避免并发写入拆散记录或轮换后继续写到旧句柄。

同时控制单文件、备份份数、保留天数与受管文件总量。明确日期时区、当天是否计入和清理触发时机。清理只处理固定目录中符合精确命名规则的普通文件；不删除自定义日志、无效日期文件、符号链接、业务数据库或维护文档。

新文件限制访问权限，检查固定目录与目标文件类型，拒绝符号链接。写入、轮换、清理和锁故障均使用固定安全提示，不回显原记录或异常正文；对提示节流，避免存储故障造成告警洪水。备用提示应能独立于故障文件输出。

OMRS 的参数仅作容量设计实例，迁移时需重新选择：

| 参数 | OMRS 示例 |
|---|---|
| 运行／AI 请求日志单文件上限 | 8 MiB |
| 每个文件轮换备份 | 3 份 |
| 运行日志按日期保留 | 含当天 30 天 |
| 受管运行日志合计 | 64 MiB，超限先清理较早文件 |
| 故障提示节流 | 每进程 60 秒最多一次 |
| 跨进程目录锁等待 | 2 秒 |
| 清理触发 | 下一次日志写入，无额外后台服务 |

这些限额不是永久保存承诺；按容量清理的内容与已省略原文无法由导出补回。

## 导出不能扩大文件读取权限

日志清单和下载限定固定目录及明确文件类型，客户端不能传任意路径。拒绝路径穿越、目录、符号链接和范围外文件，不读取配置、业务库或维护任务文档。

沿用目标产品的鉴权和来源校验；列表与下载避免缓存敏感内容。限制数量和总字节数，文件在列出后变化或不可读时返回明确结果。临时归档限制权限，并在成功和失败路径清理。

导出保留现有字节时明确说明内容性质，不能把“可下载”称为“已脱敏”。若用户需要脱敏版，应作为独立转换功能设计与验证。

## 验证打在故障与业务边界

按实际实现选择检查，不因为使用本文就运行无关全套测试。

| 场景 | 要观察的行为 |
|---|---|
| 事务成功、回滚、无效输入与幂等重试 | 只有本次新提交产生成功诊断；正式回执正确 |
| 写盘、轮换、清理失败与锁竞争 | 已完成业务仍成功；安全提示可见且有界 |
| 多线程／多进程追加与跨阈值轮换 | 完整记录不互相拆散；容量及等待受控 |
| 过期、总量超限、陌生文件和链接 | 只清理归本系统管理的文件 |
| 超大 AI 单条与默认关闭开关 | 仍可解析；省略明确；关闭时不写原文 |
| 导出范围、权限、临时件和文件变化 | 无越界读取；失败路径也清理临时件 |
| 页面提供日志查询或下载 | 隔离服务与真实浏览器完成用户主路径 |
