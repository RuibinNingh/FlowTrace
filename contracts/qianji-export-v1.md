# 钱迹原始导出兼容 v1

本契约描述流迹对钱迹实际 CSV/XLSX 导出的兼容规则，不代表钱迹服务端规则已还原。实现入口为 `server/src/flowtrace_server/imports/qianji_export.py`，大批流程复用 [import-stages-v1](import-stages-v1.md)。旧公开 V10 模板继续使用原有规则。

## 文件识别与限制

识别以下 19 列的实际导出：`ID、时间、账本、分类、二级分类、类型、金额、币种、账户1、账户2、备注、已报销、手续费、优惠券、记账者、账单标记、标签、账单图片、关联账单`。列集合可包含实现允许的可选列；必须有 `ID、时间、账本、类型、金额、币种、关联账单`，重名或未知列拒绝。没有 ID 的公开模板仍按原 profile 解析。

钱迹样本的 XLSX 声明范围为 A1，实际有 106 个物理行；读取时重置这个不可信范围，仍执行解压/XML、公式、实际行列和处理预算限制，不以 Excel 范围声明替代真实计数。时间按显式目标时区解析，实际导出支持秒，金额按冻结币种精度精确解析，不经浮点。

普通预览入口保持 **50 行 / 5 MiB**。105 条等完整导出使用现有持久暂存：上传原件 → 解析 → 资源映射 → 整批预览 → 用户确认 → 原子发布/同步；不把文件拆成多笔独立金融提交。stage 原件、分页和发布限制仍以既有契约为准。

## 稳定来源与资源

- 原始 ID 必须为 1–128 位 ASCII 字母、数字、下划线或连字符；XLSX 的 ID/关联账单必须为文本，拒绝可能已损失精度的数值 ID。
- 来源标识为 `uuid5(NAMESPACE_URL, "qianji-export-v1:" + 原始ID)`；与文件 hash 和行序无关。正式目标标识继续走现有按用户隔离的来源重写，不直接把原始 ID 写成业务 UUID。
- 两遍有界处理先收集来源/关联/金额元数据，再流式转换；备注等私人单元格不加入索引或诊断日志。重复 ID、无效 ID 明确拒绝，合法同额不同 ID 保留。
- 实际导出的分类映射键为 `收入 · 名称` 或 `支出 · 名称`，优先二级分类名称；退款/报销到账使用支出分类。收入和支出即使同名，也须分别映射到对应类型的分类；公开 V10 模板的旧名称键保持原样。
- 账户为空就保留为空，不猜测现金账户，不制造资产分录。其他账户、标签、图片迁移继续服从原有显式映射、原图授权与完整性规则；仅有图片链接不构成已迁移图片。

## 退款与报销到账

`退款` 转为既有 `bill_type=refund`，以原始“关联账单”唯一定位同批原支出；`报销入账` 同理转为 `reimbursement`。分配保留来源 UUID、精确 `source_amount_minor` / `receipt_amount_minor`，`income_component_minor=0`，不转成普通收入。本 profile 仅接受同币关联，不推算汇率。

缺少来源、关联格式错误、循环、来源不是支出/报销支出、跨账本、跨币种、累计回款超过来源金额均明确拒绝。已报销标记显示已有回款而文件没有对应可核验明细时拒绝，不猜测已回款金额。本次实际样本的 3 条退款分别与原支出、金额逐条核对。

正式写入仍由现有权限、预览、去重、原子事务与撤销规则复核；解析成功不是提交凭证，也不表示完整高级回款 UI/typed 重构已经完成。

## 错误与兼容性

界面显示固定中文原因、物理行/字段、错误码及合法请求 UUID；异步任务还显示任务 ID。常见代码包括 `unsupported_qianji_columns`、`too_many_rows`、`qianji_duplicate_id`、`qianji_reference_missing`、`qianji_refund_exceeds_source`。不向用户回显原始异常或任意响应正文。

普通 parse 的 `include_diagnostics=true`、stage rows 的同名查询参数显式选择返回 `request_id`；省略时保持旧客户端原响应键集合。HTTP 路径、操作数、旧 50 行上限和旧 V10 键不变。唯一导出见 [openapi.json](openapi.json)。

`import_parse_checked` 仅记录固定格式/错误码、行、字段、数量、stage UUID 和请求 UUID；它可能早于外层作业事务提交，不作为账务成功回执。容量、硬开关、私有权限和后台再投影导出见[诊断模块](../AI/modules/diagnostics.md)。
