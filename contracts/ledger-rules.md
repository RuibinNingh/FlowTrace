# 账务、统计与计划规则 v1

版本：1.0；日期：2026-10-21。配套：[金额时间](money-time.md)、[权限](permissions.md)、[黄金样本](fixtures/ledger/README.md)。C=静态客户端线索，G=官方指南说明，N=FlowTrace 明确默认；这些不等于钱迹 4.5.4 运行实测。

## 单一账务事实

一笔账单只能属于一个账本（G）。同用户多账本可用同一私人账户（G）；账户余额按账户所有有效分录复算，账本统计按账单所属账本计算。账单可不关联账户，此时只影响收支/预算，不制造假现金账户。

API 与领域统一 `bill_type`：income、expense、transfer、credit_repayment、loan_borrow、loan_lend、loan_collect、loan_repay、refund、reimbursement、balance_adjustment。`source` 是 manual/import/recurring/installment/auto，不改变账务类型；自动识别候选只有用户确认后产生正式账单。

`flags.exclude_from_statistics` 与 `exclude_from_budget` 独立（C）；均不取消账户影响。修改、删除先撤销旧影响再应用新影响，账单/分录/关联/回执/同步变化同事务。拒绝的操作整个状态不变；幂等重试复用正式结果。

优惠采用 `gross_amount_minor`、`discount_minor` 可选字段，均为账单币种；`money.amount_minor=gross_amount_minor-discount_minor` 是实际支付额，统计/账户/退款上限都只使用实际额，不再扣第二次优惠。折扣不得负数或超过原额，结果为零不生成正式费用；原价 120、优惠 20、实付 100 的预算消耗为 100。手续费是独立有 ID 的关联费用分量，删除主转账时一起撤销，不能客户端和服务端各加一次。优惠与原价规则是 N。

| 类型 | 账户有符号分录 | 收支及预算 |
|---|---|---|
| income | 收款账户 +金额 | 收入；不消耗预算 |
| expense | 付款账户 -金额 | 支出净额；可消耗预算 |
| transfer | 转出 -额，转入 +额 | 本金非收入/支出；手续费作为关联 expense 仅计算一次 |
| credit_repayment | 付款资金 -本金，信用卡 +本金 | 还本金非收支；手续费/利息独立 expense |
| loan_borrow | 资金 +本金，应付债务 -本金 | 非收入，不消耗预算 |
| loan_lend | 资金 -本金，应收债务 +本金 | 非支出，不消耗预算 |
| loan_collect | 资金 +本金，应收债务 -本金 | 本金非收入；利息独立 income |
| loan_repay | 资金 -本金，应付债务 +本金 | 本金非支出；利息独立 expense |
| refund/reimbursement | 实收账户 +实际回款 | 冲减源支出；不把同一回款再次全部算普通收入 |
| balance_adjustment | 当前额到目标额的差值 | 默认排除收支/预算；账户调整记录可追溯，不伪造经营收入 |

余额调整保存后冻结当时的有符号分录；target_balance_minor 是该次调整的历史目标，不是对以后余额持续生效的约束。修改旧调整的备注、日期/时间、分类/标签/附件或独立标记时，若 bill_type、account_id、money、target_balance_minor 均未变，保留原分录方向和金额；仅更新所选元数据及分录业务日期。不能用当前余额重算方向。例：10000→支出1000→调整+500至9500→收入1000后为10500，改旧调整备注仍为10500，删除旧调整撤销原+500后为10000。明确改变资金字段时才用“当前余额减原有分录”作为基线核算新目标，失败整项回滚；缺少原有符号分录时明确 unavailable，不从正金额猜方向。该规则为 FlowTrace 数据可靠性默认，非原应用实测。

普通转账要求两账户存在、不同且有权使用（C）；债务借贷账户不能用于普通转账（C），必须走对应债务类型。信用卡正余额表示溢缴，负余额表示欠款（负号提示为 O）；债务应付通常负、应收通常正，但核销/超还需明确业务操作，不静默换类型。

资产总览对 `include_in_net_assets=true` 的账户，在估值日换算后计算：资产=正余额和，负债=负余额绝对值和，净资产=资产-负债。隐藏仅影响展示，不等于排除总资产。期初余额无收支/预算影响；资产开关不抹掉原有账户分录。

信用卡账期 N：账单日/固定还款日按月末截短，账单日当天业务日期计本期，次日进入下期；固定还款日取账单日之后首个对应日期，或明确采用“账单日后 N 天”。应还额由本期消费、费用、退款和已还本金计算，额度与免息期只是展示/提示，不产生第二笔债务或费用。具体发行方规则不自动推断；用户可填实际账单额核对，利息须显式入账。

## 退款、报销与跨期归属

退款/报销为有自己日期、入账账户、币种和金额的回款记录；源 expense 与回款用 `allocations` 关联：

```json
{"source_bill_id":"expense_1","source_amount_minor":"2000","receipt_amount_minor":"2000"}
```

`source_amount_minor` 使用源单币种；`receipt_amount_minor` 使用回款币种。跨币种分配必须明确双方金额与锁定汇率，不能比较不同币种裸整数。一个回款可关联多笔有权限的源单；每笔都单独校验，不允许跨越无权读取的账本。

对源单 P，累计源币退款 R、报销 E 满足 `0<=R+E<=P`。净支出 `P-R-E`，剩余可关联额同值；标记待报销不增加资产应收，也不提前冲减消费，实际报销到账时才冲减。回款本身账户 +实收额，原单账户不重复加钱。

P4-02补充契约于2026-10-22冻结，可选追踪字段、无标识权威来源聚合、兼容与实施状态见[退款报销v1](refund-reimbursement-v1.md)。`receipt-tracking-v1`须在实际实现后才声明；本段落地不表示当前运行服务已接受新字段。expense实际支付额P必须严格大于0，账户余额/预算允许0不改变此约束。

超额退款保留为显式能力：`income_component_minor` 使用回款币，`sum(receipt_amount_minor)+income_component_minor=回款amount_minor`；仅 refund 可以有非零收入分量，UI 明确显示分配及超额收入，用户确认后原子提交。该分量按回款日期计普通收入；不把源单减成负支出。reimbursement 的收入分量固定 0，超剩余应报 `allocation.exceeds_remaining`。旧电脑版变更日志提到超原额退款呈现收入（G，非目标端实测）；本节分量结构与跨期规则为 N。[钱迹电脑版变更日志](https://docs.qianjiapp.com/change-log/change_log_pc.html)

**默认统计口径 N：**退款/报销冲减归原单业务日期与类别，所以十月垫付、十一月报销会更新十月净支出和预算；现金流另按真实回款日期展示。净支出永不为负；报表必须能展示原额、退款、报销、净额。回款 flag 继承源单对应贡献的排除语义，不允许回款自己切标记绕过原单规则。超额收入分量可有自己的收支排除标记。

`exclude_from_statistics` 仅使源单净费用不进主收支；`exclude_from_budget` 仅使源单净费用不进预算。分录和实际现金流不受这两项排除。退款/报销累计冲减报表额采用 money-time 的累计比例法，跨币种差额不偷偷改写原币账务。

关联维护采用方案A：原单有有效分配时，普通更新若实际改变类型或Money的币种/精度/金额，或者删除，均拒绝`bill.has_allocations`；增额或仍高于已分配额的减额也不能通过普通更新。比较前后实际值，完整表单携带相同Money不算更改。格式/严格schema错误仍可在领域检查前拒绝。金额更正可以在用户明确确认的typed `revise_source`中调整，最终仍须守恒；该复合能力的实现状态见补充契约，普通`saveBatch`不是远端原子事务。普通修改备注/标签不破坏关联。

关联本身不额外禁止合法账户、业务日期/精确时刻或类别/标记更改；这些变更继续遵守当前账本/账户写权限、归档/开户日、时间与冻结reporting校验。改账户只撤回/重记原单分录，改期使源单净支出/预算随原单期间变化；既有回款的账户、金额和历史时刻保持。回款删除或解除分配会恢复源单净支出/可报销额，并按回款是否保留决定撤销入账还是把未分配部分转成显式收入；不得产生未归属金额。复制原单不复制退款/报销关联和同步身份。

报销解除全部关联而保留回款时，必须在同一显式确认操作中转换为普通 income；不能留下 allocations 为空却仍标 reimbursement 的记录。部分解除同样要显式拆出独立收入分量/记录，否则拒绝，不隐式扩大源单剩余。

## 预算与报表

所有统计基于有效账单与源单净额，不基于当前账户余额，不把转账/借贷/还款本金当收支。每周期字段：income_minor、expense_minor、net_minor=收入-支出、budget_eligible_minor（排除预算标记后、尚未筛分类的净费用）。分类汇总之和等于总览；零分母不显示假均值。

预算是 `(book_id, period, report_currency)` 作用域，不改变账务。三模式按当前官方指南 G 固定；不是目标 4.5.4 实测：[钱迹预算指南](https://docs.qianjiapp.com/vip/vip_budget.html)。

| 配置 | 总预算上限 | 占用规则 |
|---|---|---|
| 仅总预算 T | T | 所有符合预算标记的分类净费用 |
| 仅分类预算 | 预算分类额度和 S | 仅预算分类及后代的净费用 |
| 总预算与分类 T>S | T | 全部分类；未设分类归“其他”，其他额度=T-S |
| 总预算与分类 T=S | T | 仅预算分类，其他分类不消耗总预算 |
| 总预算与分类 T<S | 拒绝 `budget.total_below_categories`（N） | 保持旧配置/统计不变；官网未说明该分支 |

一级/二级分类预算允许分别使用，但同周期配置不能同时预算一个父分类及其子分类，以避免上限/占用双计；冲突返回 `budget.overlapping_categories`（N，原型需补验）。一个账单最多落一个预算分组；分类预算结果计该分类后代净费用。预算剩余=上限-占用，允许负数以显示超支。设置“沿用上期”只复制额度和分类，不复制支出；已存在本期配置不被后台重复覆盖。

## 分期、周期与存钱

分期计划必须选择确认模式（N）：

- `expense_schedule`：每期生成本金支出和费用，创建计划时不再记一笔总支出。已执行期数仅用于迁移映射，不能再次生成已经存在的账单。
- `debt_repayment_schedule`：先前消费已记在信用卡/债务账户，每期本金仅还债，费用另记支出；不得再次确认消费本金。

本金和总费用按末期补余数分摊。每次发生键=`plan_id+occurrence_index`，重跑复用原账单；已生成账单允许普通维护，删除不会把发生键变回未执行而自动再生。终止只取消未发生期；提前结清记录尚未还本金及显式确认的实际费用，原子生成结清记录/终止后续，不能再生成原末期。计划修改只作用未来；钱迹原分期任务不可修改为 G，流迹首版保存后同样锁定原计划，修改通过终止新建处理。

周期规则只产生明确类型的账单，由服务端 worker 唯一生成；每期账务与普通账单相同。修改规则不改历史账单；暂停恢复后按明确补跑规则执行。日期、工作日日历、幂等和租约细节遵循时间及 jobs 契约。

存钱计划的灵活/365/52周/逆向/定额/12存单/36存单只是目标和安排，不在创建时改变余额。存入记录可为“进度记录”或“关联转账”：前者只改变进度且明确无资金移动，后者关联一次普通 transfer，不再生成支出；修改/删除转账须同步调整进度。各模式具体到期序列在独立夹具列出；52周标准以每周基础额×1..52，逆向×52..1；365模式以基础额×1..365；12/36存单按每月等额，定额按所选周期，灵活无自动存入。到期不自动移动资金，只形成待处理安排。

## 有限证据与变更

独立统计标记、实际金额扣退款/报销与转账校验具有 C 线索；预算三模式和个人多账本共用账户具有 G；跨期归属、超额分量、账户共享投影、分期舍入/模式、存钱数列为 N，见 [证据矩阵](../AI/plans/flowtrace/evidence-matrix.md)。遇到新证据先修改契约版本与黄金样本，再调整实现；单端不能自行改变口径。
