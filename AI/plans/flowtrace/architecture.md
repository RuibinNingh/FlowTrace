独立构建与发布约定：

- Flutter 产出 Android 安装包、Web 静态文件和 Windows 包；构建不导入 Python 源码、不要求服务端在线。联网测试可以使用固定协议替身，正式集成验收仍连接真实隔离服务。
- 服务端产出 Python wheel、锁文件和部署材料；Jinja2 模板与管理静态资源进入 wheel。服务端安装不要求客户端源码和 Flutter SDK，用户 Web 可独立托管或放在同一 Nginx 下。
- API 使用 `/api/v1`；后台使用独立 `/admin` 路由和管理权限。共同域名只是推荐部署拓扑，独立构建不等于必须使用不同域名。
- `contracts/openapi.json` 从服务端模型导出，由兼容检查验证；文档、客户端生成层与服务端契约不能各维护一套互相矛盾的字段定义。客户端业务模型不直接依赖服务端数据库模型。
- 兼容策略采用先加字段、允许旧客户端忽略新增可选字段、最后移除旧字段；不兼容更改升级协议版本。服务器返回最低客户端/同步协议要求，升级提示出现时仍允许查看已经持有的本地账单，不执行不兼容写入。
- Python 运行时及依赖选择受支持、通过三端与部署预研的版本并锁定；本计划不固定未经验证的“最新版本”。Flutter SDK 版本、数据库主版本、操作系统软件包及系统库版本写入构建记录和运行手册。

## 4. 客户端、服务端与平台职责

Flutter Repository 负责提供本地可读模型、事务保存账单及待发送操作、合并远端确认、向 UI 暴露“本地已保存/等待同步/已同步/冲突/失败”。离线保存不显示为服务端已确认。输入校验和统计口径通过共用样本与 Python 对照，服务端重新校验所有不变量和权限。

服务端是在线共享状态、当前成员权限、作业执行与同步回执的权威；本地待同步数据是尚未提交的用户意图。服务端不能直接相信客户端上传的 `user_id`、余额、权限、时间戳或汇总统计，不能将客户端任意表变更透传为数据库写入。

| 平台 | 本地持久化默认 | 必须单独验证的差异 |
|---|---|---|
| Android | SQLite 事务库，受控附件目录，系统安全存储保存长期凭据 | 真机权限、应用被杀/升级、后台限制、存储不足、自动记账原生桥接 |
| Windows | SQLite，经桌面适配层访问；文件与系统凭据存储独立实现 | 文件锁、多实例、路径和卸载行为、窗口/键盘、附件与备份选择 |
| Web | Repository 下独立持久化适配；默认预研 SQLite WASM + OPFS，失败时评估 IndexedDB 事务实现 | HTTPS、WASM/worker/必要响应头、浏览器支持、配额/持久化授权、隐私模式、多标签页、用户清除站点数据 |

Flutter 官方 SQL 示例分别使用移动/桌面插件，Web 支持不属于该示例已覆盖范围；不能把“Flutter 支持 Web”当作本地存储插件或 Android 后台能力自动等价。[Flutter SQL 持久化](https://docs.flutter.dev/app-architecture/design-patterns/sql)

Web 存储必须在立项预研完成写入、刷新、断网、重启浏览器、多标签页与容量不足用例，再冻结适配器。`navigator.storage.persist()` 只能请求更强持久性，不能阻止用户主动清理；本地数据不是服务端备份。没有可用持久化时，界面明确降为联网使用，不把内存缓存的草稿报告成离线可靠保存。暂不支持的浏览器能力应显示原因并保留服务端使用入口。[WHATWG Storage](https://storage.spec.whatwg.org/)、[SQLite WASM 持久化](https://sqlite.org/wasm/doc/trunk/persistence.md)

Web 离线还需要应用壳可启动。当前 Flutter 官方说明不再默认生成/维护缓存 service worker，因此 `flutter build web` 不能证明已具备离线 PWA。计划自行配置受控 service worker：首次联网完整下载并校验本版本入口、字体、渲染/WASM、存储 worker 与必要资源后，才显示“已可离线使用”；首次从未访问过的设备无法离线打开。缓存限定公开静态应用资源，`/api/v1`、`/admin`、认证、备份和私人附件不混入通用网络缓存。新版本按构建标识原子切换，旧资源保留到所有使用中的页面可安全切换；提示用户刷新前先确保 outbox/草稿持久化，数据库迁移与应用版本兼容。离线时继续使用完整旧版本，不能拼装新旧资源。验收包含关闭浏览器后断网冷启动、升级下载中断、旧 service worker 清理、多标签页及失败回退。[Flutter Web FAQ](https://docs.flutter.dev/platform-integration/web/faq)

本地库、附件、游标及待发送队列按“服务器实例 + 用户 + 本地资料空间”隔离。切换服务器或账号不能把旧队列自动推给新账号；注销或撤权先处理未传草稿，再清理相应缓存。自动记账/OCR 用平台接口隔离，Android 实现独立验收，Web/Windows 使用各自可用的截图、文件或手动入口。

## 5. 精确金额、业务时间与数据事务

### 5.1 金额与币种

- 账单金额使用 `currency`、`currency_scale`、`amount_minor`。`amount_minor` 在 API/JSON 中是十进制整数字符串，例如 `"12345"` 与 CNY 的 2 位小数表示 123.45 元；账单录入值为非负，账户分录使用带符号数。所有修订、游标中的大整数同样使用字符串，避免 Web 的 JavaScript 数值边界截断。
- Python 使用 `int`，Dart 领域模型使用 `BigInt`；PostgreSQL 使用 `BIGINT`，Android/Windows SQLite 使用有符号 64 位 `INTEGER`。在入口校验单笔、账户累计及聚合范围；拒绝溢出，不截断。Web 持久化适配若不能无损往返 64 位整数，就使用十进制文本/BigInt 桥接，不降为浮点。
- 币种最小单位不能一律写死为“分”。支持 0/2/3 位等精度，历史账单保留当时精度；币种元数据变更不得重新解释旧金额。
- 汇率单独用十进制定点字符串传输，服务端 `Decimal` + PostgreSQL `NUMERIC(38,18)` 为初始默认；客户端用十进制/有理数运算，不借用 `double` 做最终账务计算。使用该范围前通过大数、极小汇率和跨币种样本验证。
- 跨币种转账同时存原币转出额、目标币转入额、当时汇率与手续费。统计折算保存所用基准币、汇率来源及日期；修改当前汇率不追溯改写历史账单。分期/分类分摊采用明确舍入与尾差分配，分摊之和必须等于原总额。
- 以上是 FlowTrace 推荐契约。实现时把具体输入上限、舍入模式和样本固化到 `contracts/money-time.md`，由 Dart/Python 共用用例验证。PostgreSQL 官方将 `numeric` 定义为精确十进制、`real` 为非精确数值，这是选型依据。[PostgreSQL 数值类型](https://www.postgresql.org/docs/current/datatype-numeric.html)

### 5.2 时间

分开保存：`occurred_at`（带偏移的业务发生时间）、`business_date`（用户看到的记账日期）、`business_timezone`（IANA 时区）、`created_at/updated_at`（服务端 UTC 写入时间，不宣称等于数据库精确提交时刻）。旧账、导入账及按天录入保留用户指定业务日期，不能由服务器当前时区重新生成。日期型任务用日期与任务时区表达，不虚构精确发生时刻。

同步排序依靠服务端修订，不依靠设备时间。周期任务保存时区、当地执行规则、月末及夏令时处理规则。计划与维护记录日期仍使用 Asia/Shanghai；应用的账本时区允许用户配置。

### 5.3 实体与事务

| 范围 | 计划实体 | 关键约束 |
|---|---|---|
| 身份 | users、sessions、invites、admin_roles | 邀请单次兑换；令牌保存哈希；禁用可撤销会话 |
| 权限域 | books、book_memberships、accounts、account_permissions | 私人用户域、共享账本域分别授权；账户归属不随账本分享隐式改变 |
| 核心账务 | bills、account_entries、bill_links、categories、tags | UUID 业务标识；明确类型和源单；账单、账户影响与修订在同一事务提交 |
| 计划任务 | recurring_rules、installment_plans、job_runs | 规则版本、单次发生标识和已生成账单可关联 |
| 同步 | sync_scopes、changes、operation_receipts、device_cursors | 修订校验、已提交顺序游标、墓碑、幂等回执 |
| 文件与运维 | attachments、export_jobs、admin_audit、diagnostic_summaries | 权限随所属资源验证；运维审计与诊断分离 |

源端 UUID 可离线生成；服务端唯一约束发现相同 UUID 的不同对象时返回冲突，不静默换 ID 或覆盖已有账单。分类、标签、账户等引用对象必须存在且当前主体有权使用。

修改/删除一笔账单时，在同一事务内撤销旧账户影响、应用新影响或取消影响，并更新账单、关联退款/报销、账户必要汇总、同步变化与正式回执。转账的两个账户、手续费及币种处理必须一起成功或一起回滚。账户余额可由期初余额与有效分录复算，缓存余额不能成为唯一事实来源。读写涉及多个权限域/账户时按稳定排序获取锁，控制死锁重试。

退款、报销、分期、周期、借贷、信用卡还款分别保留领域类型和关联，不能统统退化成普通收支。统计“不计收支/不计预算”等标记独立处理，具体口径由产品契约和样本固定。SQLite 替身不能代替 PostgreSQL 的并发、锁与约束验收。

## 6. API 与离线同步协议

### 6.1 API 边界

建议接口族：`/api/v1/auth`、`/users/me`、`/books`、`/accounts`、`/bills`、`/categories`、`/tags`、`/budgets`、`/statistics`、`/sync`、`/attachments`、`/imports`、`/exports`、`/tasks`、`/server-info`。它们表示设计范围，不是已存在端点。

普通在线写入、离线重放及后台受支持的业务命令必须调用同一领域事务入口，统一权限、幂等与修订规则；不能让普通 CRUD 路径绕过同步回执。分页、排序、最大批量/正文/附件大小、错误码、追踪 ID 和 API 版本进入契约。统计接口明确原币/折算币和业务时间范围。

### 6.2 本地 outbox 与幂等

1. 本地事务同时写入用户可见数据和 outbox 操作。每次操作包含稳定 `client_id`、`operation_id`、实体 UUID、类型、权限域、`base_revision`、协议版本和所需正文；本地文件上传状态单独关联。
2. 同步器只允许同一资料空间有一个协调者。Web 多标签页通过适配器的事务与选主/锁协调；崩溃后可重新接管。前台启动、恢复网络和用户手动同步触发拉取/推送，后台只作补充，不承诺应用关闭后即时运行。
3. 服务端以认证用户、客户端和操作 ID 建唯一回执键，保存正文规范化哈希。同 ID 同正文返回已提交回执；同 ID 不同正文返回明确错误。回执与业务写入同一事务落库，网络回包丢失后重试不产生第二笔账。
4. 每个业务操作独立原子提交；一个批次可返回逐项结果。涉及多实体的转账、批量事务组等在操作内部整体提交，不能被批量分页拆散。协议明确依赖排序，前序失败时依赖操作等待，不把半成品当成功。
5. 新建后离线连续修改可在未发送前安全合并；一旦开始发送，即保留其操作 ID 与正文，后续修改成为新操作。客户端不在“请求超时、提交是否成功未知”时替换操作 ID。

同一实体的本地操作按依赖串行发送，后续操作可以引用前序正式回执的修订作为基准；只有自己的前序确认可以据此接续，遇到其他设备已修改仍应冲突。客户端保留服务端确认影子与本地待传投影，拉取或旧回执到达时不能覆盖更新的本地输入；确认、outbox 推进、影子更新及界面投影重算在一个本地事务完成。

### 6.3 修订与冲突

每个可同步实体有服务端 `revision`。更新/删除必须带 `base_revision`；只有当前修订匹配时提交并递增。SQLAlchemy 的版本列可以辅助单行校验，但不能替代领域操作与所有批量路径的显式条件更新；官方版本机制对批量 UPDATE/DELETE 有边界。[SQLAlchemy 版本计数](https://docs.sqlalchemy.org/en/21/orm/versioning.html)

| 冲突 | 推荐处理 |
|---|---|
| 两端修改同一账单 | 第二次提交返回冲突及主体有权读取的当前版本；本地保留基准、未传修改和服务端版本供比较 |
| 一端删除、另一端修改 | 不自动复活；用户可放弃本地修改，或明确以新对象另存，保留原关联限制 |
| 分类/账户已删除或失权 | 返回依赖冲突，保留草稿，要求重新选择有效引用 |
| 客户端创建 UUID 已被占用 | 正文/回执一致可复用；不同对象拒绝，重新生成 ID 必须显式修复关联 |
| 需要采用本地版本 | 基于最新修订重发一个新操作；若再次并发变更，继续冲突，不提供绕过权限的强制写入 |

默认不做金额、账户、类型等字段的自动合并，不采用“最后设备时间获胜”。用户解决冲突后触发完整账务校验；“另存一笔”要明确可能增加一笔真实账，不作为自动修复。

### 6.4 增量游标、删除和重新同步

- 同步域分为私人用户域与账本域。每个域有 `sync_epoch`、已提交修订序号与权限版本。变更列表只包含当前主体有权读取的投影；私人账户细节不混入共享域。
- 每轮同步先校验服务端当前授权域清单及成员权限版本，处理新增/撤销控制信息后再同步业务域；不能永久相信本地账本列表或令牌中旧的成员关系。撤权控制信息放在用户自己的可读控制通道中，不要求继续读取已失权账本。
- 修订分配在修改事务内锁定 `sync_scopes` 对应行，持锁到提交；领域修改、该域变更行和游标序号一起提交。多个域以稳定次序锁定。不能直接拿 PostgreSQL 独立 sequence、设备时间或事务开始时间当“提交顺序”：先取小序号后晚提交会使客户端越过未提交记录。
- 拉取会话在同一一致快照下取得各授权域的高水位向量，按 `(scope_revision, event_index)` 稳定分页。变更行保留该提交时的受控版本/投影，不使用已经被后续更新覆盖的当前行冒充旧高水位内容。一个领域操作涉及的变化以 `commit_id` 组成完整组；跨域变化在取得当前主体有权看到的全部投影后一次应用，不等待或泄露无权读取的私人部分。最后一页成功落本地库后才持久化对应游标。分页重试允许重复收到已应用变化，但不能漏收或以半笔转账刷新余额。
- 首次/全量同步在服务端一致快照中生成有期限的快照产物及其基准游标；客户端下载完成后再追赶快照之后的增量。快照未完成时不推进本地正式游标，不让长时间跨 HTTP 分页拼成不同时间的数据集。
- 删除先产生包含 UUID、类型、修订与删除时间的墓碑，参与增量同步。初始建议离线增量窗口为 90 天；活跃设备确认情况与保留期限共同决定可清理范围。超期客户端得到 `resync_required`，不可继续用旧 epoch 写入或把不存在对象当作新建。
- 全量重建先隔离保留未提交 outbox、冲突草稿和未传附件，再替换可重建缓存并重新校验/重放意图；绝不通过删库来丢弃用户未上传数据。最小幂等键/正文哈希的保留策略须覆盖可接受离线窗口；清理后旧客户端必须被 epoch/离线期限拒绝，不能因回执过期重复入账。
- 服务器备份恢复会改变历史时间线，恢复流程必须更换同步 epoch，使旧设备停止增量并核对未传操作；保留恢复点回执不足以证明恢复点之后的本地操作已经存在。

服务器恢复导致 epoch 变化时，先保留重建前完整本地快照，不仅保留 outbox。恢复点之后曾被服务器确认的账单，可能已在设备移出 outbox，却不存在于旧备份；客户端应提供差异核对与受控恢复入口，利用稳定 UUID 和修订关联判断，不能全量覆盖本地后把这些账单静默抹掉，也不能自动把所有旧账重新入账。普通协议升级与故障恢复的 epoch 变化应带安全原因码，使用对应恢复路径。

### 6.5 权限撤销

请求鉴权后，每次拉取页、推送操作、文件下载和导出下载都重新确认用户状态与相关成员权限；权限变更与写入通过同一域锁/权限版本串行化，已撤销主体不能靠旧游标或旧请求继续写入。失权返回安全的撤权状态，不附带账本当前正文。

客户端再次联网得知失权后停止相关同步、移出可见列表、清除相应已同步缓存及附件，并把尚未上传的用户意图隔离为不可继续回写的草稿，按可见性规则允许用户处理自己的输入。服务器不能即时清除完全离线设备的数据，也不能收回用户此前导出、截图或复制的内容；计划不承诺此能力。

## 7. 多用户、共享账本与管理角色

| 主体 | 默认权限 |
|---|---|
| 普通用户 | 自己的私人账本、账户、设备会话及被授予的共享账本 |
| 账本所有者 | 管理该账本成员、编辑权限及账本设置；不能因拥有账本就控制成员的私人资产 |
| 账本编辑成员 | 编辑被允许的共享账务；不能转移所有权或提升成员权限 |
| 账本只读成员 | 浏览和按产品规则导出共享账务；不能通过离线同步或导入绕过只读 |
| 服务管理员 | 用户邀请/禁用、系统配置、作业诊断、备份状态和运维审计；默认无任意浏览/修改私人账本、下载原始备份或执行恢复的权限 |
| 服务器所有者/恢复管理员 | 显式授予的高权限角色，可经再次认证、目标确认和审计下载授权全量备份、发起隔离恢复及已授权的数据切换；可能接触原始账务，不能隐式授予普通管理员 |
| 运维恢复执行身份 | 非交互系统执行身份，仅执行固定备份/隔离恢复程序；不向 Web 进程授予 root 或任意 shell 执行能力 |

账户有独立所有权：私人账户属于用户；共享账户属于账本。建议共享记账优先使用账本账户。若允许一笔共享账使用记账者私人账户，私有账户关联与分录保存在该用户域；其他成员可见共享账单和付款人投影，不得到私人余额/其他流水。修改影响他人私人账户的金额、账户或删除操作必须取得相应账户权限，默认拒绝并引导原记账者处理；此细节在 F10/F11 产品流程核验时冻结，不能只靠 UI 隐藏字段。

服务端数据访问层必须接收认证主体与资源作用域，统一执行授权；列表、聚合统计、搜索、批量操作、导入、同步、缩略图、附件原图及导出均使用同样的过滤规则。附件 UUID 难猜不能代替权限检查；共享账本邀请令牌限时、一次性并绑定角色，普通注册邀请与账本成员邀请分开。

身份默认方案：随机不可猜的短期访问令牌 + 可轮换刷新令牌，服务器只保存令牌哈希及会话状态，每次访问确认会话/用户未被撤销，便于禁用后立即拒绝在线请求。密码使用经验证的 Argon2 哈希实现；后台与普通客户端会话用途分离，管理权限每次校验。

原生端长期凭据存系统安全存储；Web 访问凭据留内存，刷新/后台会话使用 `Secure`、`HttpOnly` Cookie，并按部署设置 `SameSite`。Cookie 状态变更使用 CSRF token、Origin 校验和明确 CORS 白名单，不把长期令牌默认写入 `localStorage`。推荐业务 Web、API、后台同源代理；跨站自定义后端不能假定第三方 Cookie 永远可用，必须单独验证兼容和授权策略。

初始可配置默认：访问令牌 15 分钟、刷新会话最长 30 天；后台空闲 30 分钟、最长 8 小时。旋转时检测旧刷新令牌复用并撤销会话族；退出、改密、禁用和管理操作可撤销指定或全部设备。首次管理员使用服务器 CLI 在受控终端创建，一次性初始化后关闭入口，不随包附带默认密码。备份恢复后旧会话全部失效。

后台阻止撤销/禁用最后一个有效可恢复管理身份，角色变更以事务保护该不变量；服务器所有者可通过受控本机 CLI 恢复管理员访问，要求操作系统权限与显式目标，不依赖已失效的 Web 登录、不使用公开重置链接。恢复入口保留安全审计，不扩大普通业务账号权限。

## 8. 服务端后台面板（F22）

### 8.1 实现选择

| 方案 | 优点 | 成本与边界 |
|---|---|---|
| 服务端 Jinja2 模板，随 Python 包发布 | Python 开发维护为主；常规表格、筛选、表单足够；无单独前端构建要求；可独立于 Flutter 升级 | 与服务端同版本；复杂交互需少量 JavaScript；需正确做转义、CSRF 和管理鉴权 |
| Flutter Web 管理入口 | 可复用 Flutter 基础组件；复杂管理交互可统一技术 | 增加管理前端构建/兼容发布；角色、路由、包体和管理接口仍需独立设计，不能复用普通账号权限 |

默认采用第一项，这是轻量维护的技术选择。后台有独立权限模型和布局，不需要模仿钱迹业务端，也不改变 Flutter 业务前端的要求。FastAPI 官方提供 `Jinja2Templates` 与静态资源支持；最终管理体验仍需真实浏览器验收。[FastAPI 模板](https://fastapi.tiangolo.com/advanced/templates/)

### 8.2 首版应覆盖的能力

| 页面/任务 | 具体范围 | 验收边界 |
|---|---|---|
| 概览 | 服务/数据库版本、迁移状态、worker 心跳、失败作业数、最近备份、磁盘容量等运维状态 | 不在首页展示用户私人金额或账单正文 |
| 用户与邀请 | 生成/撤销/到期邀请、用户启用/禁用、会话列表与撤销、角色调整的受控流程 | 禁用不等于删除账务；不能通过改角色静默获得私人账本访问 |
| 配置 | 注册策略、允许来源、附件限额、任务配置、备份保留等白名单配置 | 密钥只显示是否配置；重启型配置说明生效方式；不提供任意环境变量或文件编辑器 |
| 同步诊断 | 按用户/设备/账本的有权可见运维编号查看最后同步、协议版本、游标范围、错误码、冲突计数 | 默认不显示账单备注、图片、完整请求或冲突双方正文 |
| 作业中心 | 周期/分期生成、导入导出、备份任务的状态、尝试次数、固定错误码、取消/受控重试 | 重试沿用同一业务幂等键；不能复制任务生成第二笔账 |
| 日志诊断 | 有界诊断摘要的筛选和脱敏导出，按追踪 ID 对应服务器日志 | 固定字段、数量/字节上限；无任意路径下载、无任意 journal 查询或 shell 控制台 |
| 备份恢复 | 备份清单、创建任务、校验回执、隔离恢复演练、报告；实际替换服务数据另有受控流程 | 查看状态/触发备份与下载原始包/恢复分权；后两项仅授高权限恢复管理员。面板只提交固定类型任务；恢复执行身份与 API 身份分离；恢复前再次认证与确认目标 |
| 管理审计 | 操作者、目标稳定 ID、动作、结果、请求 ID、时间和有限变化摘要 | 敏感修改审计与正式变更同事务持久化；普通管理员不可编辑审计 |

后台不提供默认“任意表 CRUD”界面，也不提供任意 SQL 或 Python 执行。导入导出、系统备份与用户账本导出分别定义读取权限。管理操作失败不能显示明文配置或原始异常；状态页不能靠读取日志来判定账务是否提交。

## 9. 周期、分期与独立 worker（F14/F15）

API 仅验证并保存规则/作业，不在每个 Uvicorn 进程启动独立定时器。独立 worker 扫描 PostgreSQL 作业表；初期可以只有一个进程，但必须通过多个 worker 同时运行的正确性验收。

1. 周期规则保存时区、下一业务发生日期、停止条件和规则修订；分期计划保存本金/费用、总期数、尾差和每期标识。每次发生有稳定键，例如“计划 ID + 发生日期/期号”；暂停/恢复和规则修改明确哪些未来期受影响。
2. 到期调度在事务中通过唯一约束写入待执行实例；worker 使用 `FOR UPDATE SKIP LOCKED` 领取队列行，保存有期限租约、持有者、领取代次与尝试次数。提交结果时核验领取代次；失去租约的旧 worker 不能覆盖新尝试的状态或提交过期结果。该用法只用于作业队列，不用于一般同步查询；PostgreSQL 官方说明跳过锁定行会形成不一致视图，适用于队列消费场景。[PostgreSQL SELECT 锁](https://www.postgresql.org/docs/current/sql-select.html)
3. 账单生成、账户影响、同步变化、发生实例正式回执及作业完成状态尽可能同事务完成。每期生成键有数据库唯一约束，即使租约失效重领、提交后进程崩溃或回包丢失，也只能复用同一结果。
4. 重试采用退避、最大尝试次数与失败队列；权限撤销/账户失效/规则暂停等永久问题不得无限重试。管理面板“重试”只重启同一实例，不建立新的发生键。
5. 客户端离线可显示预计发生项目，但服务器管理的任务由服务端唯一入账；客户端不同时生成另一个正式账单。纯本地未关联服务器的模式若以后加入，需要单独的生成权转移协议，本版不隐式混用。
6. 非数据库副作用如导出文件生成采用暂存文件、校验、原子完成元数据和孤儿清理。外部通知若加入，只能承诺可重试与去重，不能把数据库事务扩张为所有外部副作用的绝对恰好一次。

服务中断后按规则补齐遗漏日期，限制每轮补齐数量并展示进度；断线客户端下次同步获得已生成账单。月末、闰日、跨时区、分期尾差、暂停后恢复和服务器停机补跑都进入固定验收样本。

## 10. 附件、导出与一致备份

附件位于 Web 根目录之外，用服务器生成的存储键访问；数据库保存所有者/账本域、文件哈希、大小、类型、引用状态。原文件名只作清洗后的显示，不参与服务器路径拼接。上传流限制总大小与类型，生成缩略图也走受限处理；拒绝路径穿越和符号链接越界。计划初始附件上限为每个文件 10 MiB，可在产品验收前按实际样本调整。

上传先暂存、校验，再原子移动并提交关联；故障产生的未引用文件用带宽限期的垃圾回收处理，不能清理未完成操作仍引用的附件。客户端有未传图片时显示附件待同步状态，不能只同步账单正文就宣称附件已备份。下载经资源权限检查，短期导出文件在每次下载时检查会话、权限和有效期，不返回长期公开链接。

用户导出只包含授权范围；系统备份是运维权限，不能用它替代普通用户导出。备份包含数据库、附件、版本与迁移标识、哈希清单及必要的恢复说明；秘密配置单独加密保管并限制访问。初版采用短维护窗口暂停业务写入与 worker、等待在途事务完成，再制作逻辑数据库备份与附件清单，以获得可解释的一致恢复点；客户端在维护期间继续保留本地待传操作。

备份完成须校验文件和清单后才出具正式成功回执。恢复到隔离数据库/附件目录和独立端口，检查用户、账本、余额、权限、附件哈希、任务状态与登录；禁止隔离环境发送通知或连接生产控制入口。初始运维目标为每日备份、最近 7 个日备份/4 个周备份/6 个月备份，建议 RPO 不超过 24 小时、隔离恢复 RTO 不超过 2 小时；这些是待测试的目标，不是已经测得的 SLA。至少一份加密副本放在与主机失效域不同的位置。

真正切换恢复实例时先进入维护状态、停止任务，验证目标后更换同步 epoch、撤销旧会话，并记录恢复点；旧客户端需要重新核对本地未传修改。SQL dump、文件系统备份和 WAL/PITR 是不同技术，不能把“复制运行中的数据目录”当作可靠备份；初期选择经过演练的逻辑备份，后续按 RPO 需求再评估 PITR。[PostgreSQL 备份恢复](https://www.postgresql.org/docs/current/backup.html)

## 11. 运行诊断、正式回执与审计（F21）

按[运行日志设计参考](../../../.agents/skills/repo-collaboration-logging/references/runtime-logging.md)区分四类记录：领域事实/幂等回执、持久管理审计、有界运行诊断、`AI/logs/` 的维护任务证据。它们不能相互替代。

- 正式回执和必要管理审计与相应变更同事务提交；业务已提交后才输出“成功”诊断。重复回执复用不记录为一次新入账。
- API/worker 采用结构化 stdout，由 systemd/journald 收集，避免多进程各自轮换同一个文件；Nginx 访问日志使用系统维护的轮换机制。部署预检确认目标 systemd 支持的选项，支持时给 FlowTrace 独立日志 namespace/预算，否则明确共享日志预算，不擅自覆盖全机策略。
- 有界白名单字段为 UTC 时间、服务、级别、事件码、request/operation/job ID、匿名或受限稳定用户 ID、结果、耗时、有限计数。默认不记录金额、账单备注、密码、Cookie/Authorization、邀请/刷新令牌、图片/OCR 原文、完整请求体或异常正文。
- 管理面板读取独立的 `diagnostic_summaries` 安全投影，默认保留 30 天；原始服务器诊断仅供受限运维身份查询。摘要不能恢复被省略的正文，不称为完整调用回放。
- 推荐诊断总预算先设为 256 MiB、最长 30 天、单条不超过 16 KiB，超限按完整记录省略并标识。OS 日志预算、摘要行数和导出总量均在部署预研中配置与测试；维护日志不随程序日志清理。
- 非关键诊断写入失败不把已提交记账改判失败，使用节流的安全提示呈现；需要事务持久性的正式回执/审计写入失败则回滚本次变更。日志失败与领域失败使用不同结果码。
- 日志导出限定固定数据源与时间/数量上限，拒绝路径参数、符号链接和任意文件名；临时件在成功/失败时清理。AI 原始请求/响应调试默认关闭，任何未来开启都需单独定义范围、时限和可见性。

以上均待实现；仓库当前的 skill 只提供方法和模板，不含运行日志设施或自动门禁。journald 的容量与保留配置应以目标发行版支持项为准。[journald 配置](https://www.freedesktop.org/software/systemd/man/latest/journald.conf.html)

## 12. Linux 原生部署与升级

推荐发布目录为 `/opt/flowtrace/releases/版本标识/`，活动版本软链接 `/opt/flowtrace/current`；数据放 `/var/lib/flowtrace/`，受限配置放 `/etc/flowtrace/`。Web 进程以专用低权限系统用户运行，代码目录只读，可写目录限附件、暂存等必要位置；备份恢复的高权限执行身份与应用进程分开。

阶段边界与总计划一致：P1 的 Linux 部署只是隔离工程演练，P2 的后台最小管理能力用于开发测试和个人自用；P5 在产品范围定义的 A01–A07 后台基础能力全部就绪后，才安排受控朋友试用。P8 才完成正式 Linux 安装、升级、备份恢复与交付验收。早期能启动服务不能提前代表已经适合朋友使用或正式交付。

推荐顺序与交付要求：

1. 在干净 Linux 虚拟机核对发行版、Python/数据库版本、磁盘与时区条件，原生安装 PostgreSQL、Nginx 等系统包，建立隔离的测试数据库与服务账号。运行时数据库账号无超级用户、建库或任意文件权限；迁移身份单独配置。
2. 验证发行包哈希，创建本版本虚拟环境，从锁文件安装并核对哈希。生产依赖不临时解析浮动版本；私密配置不入 Git，也不写进命令行或日志。数据库 URL、密钥、允许来源、附件根目录和可信代理配置有示例与启动校验。
3. 先做可恢复备份，在部署入口单次执行经过审阅的 Alembic 迁移；禁止每个 API worker 启动时竞相迁移。自动生成迁移只是候选，必须人工复核数据变换、约束与大表锁风险。[Alembic 自动生成](https://alembic.sqlalchemy.org/en/latest/autogenerate.html)
4. systemd 分别管理 API 与 worker，设置非 root 用户、工作目录、必要可写目录、优雅停止、失败重启与重启速率上限。API 默认绑定 loopback/Unix socket，PostgreSQL 不直接开放公网。服务进程管理与 Uvicorn 多 worker 是不同职责。[FastAPI 手动运行](https://fastapi.tiangolo.com/deployment/manually/)、[systemd 服务](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)
5. Nginx 终结 HTTPS，转发固定 `/api/v1`、`/admin`，可独立提供 Flutter Web 静态文件。配置上传限制、超时、可信转发头、允许主机、静态缓存版本与证书续期；服务端仅信任已配置代理，不能盲信任外部 `X-Forwarded-*`。鉴权/管理响应不进入公共缓存。[Nginx 反向代理](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)
6. `/health/live` 只证明进程存活；`/health/ready` 检查数据库可用、迁移兼容与必要存储；后台再展示 worker 心跳/作业延迟/备份时间。公开健康响应不回显配置或详细异常。依赖不可用时 readiness 失败，不能靠持续重启进程掩盖数据库故障。
7. 配置持久日志、容量告警、备份定时与隔离恢复演练；给出首次管理员创建、用户邀请、配置检查和测试数据清理命令。恢复脚本校验目标目录、数据库与隔离标识，不能默认覆盖生产。
8. 升级使用新版本目录和虚拟环境，先验迁移兼容、再切换链接与重启、最后验证健康和关键读写。保留上一发行包和构建清单。旧客户端仍可能在线，数据库/API 优先采取兼容式扩展迁移。
9. 应用回滚与数据回滚分开：旧代码与新 schema 兼容时可以回切；不兼容时保持维护状态，选择修复向前或按已验证备份恢复流程处理。不可盲目自动执行数据库降级，更不能回滚到会漏掉新记账数据的旧快照而不说明后果。

预定开发命令，须工程建立后才可执行并把真实结果写入模块文档：

| 工作目录 | 命令 | 验证目的 |
|---|---|---|
| `apps/flowtrace` | `flutter analyze`、`flutter test` | 静态检查、领域/组件测试 |
| `apps/flowtrace` | `flutter build apk`、`flutter build web`、`flutter build windows` | 在具备各平台工具链的主机分别构建；Windows 构建不等同 Linux 服务端构建 |
| `server` | `python -m pytest tests` | 使用开发依赖和隔离 PostgreSQL 执行后端验证 |
| `server` | `python -m alembic upgrade head` | 仅对显式配置的隔离或已授权数据库迁移 |
| `server` | `python -m uvicorn flowtrace_server.main:app --host 127.0.0.1 --port 18080` | 隔离 API 启动；此入口是计划目标 |
| `server` | `python -m flowtrace_server.worker` | 连接隔离数据库的独立 worker |
| 仓库根目录 | `python -m pytest tests/contracts tests/e2e` | 使用服务端虚拟环境解释器与已就绪的浏览器/设备执行跨模块验收 |

Flutter 各设备集成测试、OpenAPI 导出、备份/恢复和发行脚本的具体命令，在对应预研完成后固定到运行手册，避免把尚不存在的脚本报告为可运行。隔离数据库、设备和浏览器未就绪时记录未验证原因，不把 `flutter` 命令存在当作 Android 构建或真机测试已可用。

## 13. 架构风险与必须通过的验收

| 风险 | 必须验证的场景与结果 |
|---|---|
| 多端账务漂移 | 转账、退款、报销、信用卡还款及修改/删除在本地与服务端得到相同余额；事务中途故障不出现半笔影响；复算与缓存余额一致 |
| Web 金额损失 | 超过 `2^53` 的合法最小单位数值、负分录、0/2/3 位币种、汇率与分期尾差，跨 JSON/Dart/Python/数据库无损往返 |
| 重复提交 | 提交后断网、丢回包、重发、同 ID 不同正文；最多提交一次业务结果，正式回执可核验 |
| 漏拉增量 | 两事务获得序号后反向完成、拉取中并发修改、分页重试、跨域转账；不越过未提交变更、不半笔落库 |
| 并发冲突 | 改/改、改/删、已删引用、连续冲突；双方意图可见并保留，解决前没有静默覆盖或重复入账 |
| 旧设备重连 | 超过离线窗口、墓碑清理、服务器恢复换 epoch；先保全未传内容再全量重建，不复活旧删除对象；恢复前后完整快照能找回曾确认但旧备份缺失的账单 |
| 越权与撤权 | 两用户交换对象 ID，编辑成员转只读/被移除，用户禁用；列表/统计/同步/文件/导出都拒绝越权，旧会话不能继续在线使用 |
| 资产可见性混淆 | 共享账单不泄露成员私人余额和其他流水；成员不能借共享编辑能力改变他人私人账户 |
| 管理员越权 | 管理登录可执行授权运维任务，直接请求私人账单、附件、导出或普通用户业务接口仍被拒绝；普通管理员无原始备份下载/恢复权，最后管理身份撤销被阻止，本机 CLI 可受控恢复 |
| worker 重复入账 | 两进程同时领取、租约过期重领、提交前后崩溃、人工重试；每计划发生键只有一笔正式结果 |
| 任务时间边界 | 月末、闰日、夏令时、变更时区、长时间停机、暂停恢复；补跑数量与金额符合冻结规则 |
| Web 存储与应用壳失效 | 配额满、拒绝持久化、刷新/重启、清除站点数据、多标签页抢占、断网冷启动、升级半途断网；无假保存，不拼接新旧版本，已同步数据可恢复，未传内容风险明确可见 |
| 附件一致性 | 上传/关联中断、超限、未引用文件、恶意路径、撤权后的下载；无越界读取，账单不假报图片已同步 |
| 诊断影响业务 | 日志存储不可写/容量满、脱敏导出、超长记录；已提交记账仍成功，诊断不会泄露凭据或账单正文 |
| 备份无法恢复 | 数据库+附件校验清单完整，在独立数据库/目录/端口恢复后账务复算、文件哈希、任务和权限一致，旧会话失效 |
| 发布回滚丢数据 | 新旧 API 兼容、迁移单次执行、应用回切与恢复流程分别演练；不自动破坏新版本已写数据 |
| 名义上支持跨平台 | Android 真机主路径通过后分别验收 Web 浏览器与 Windows，不能以编译成功替代权限、存储与交互验收 |

每条验收由 [tasks.md](tasks.md)登记执行任务、依赖、产物和完成证据。本文件只定义目标；本轮未运行应用、数据库、真实设备、浏览器或 Linux 部署测试。
