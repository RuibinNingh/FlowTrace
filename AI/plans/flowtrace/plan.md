## 范围与默认决策

### 完整交付范围

各阶段产生可独立验收的增量，早期可运行版本只是过程成果。只有 Android、用户 Web、Windows 和 Linux 服务端/后台面板的约定范围全部验收，才能称为本计划完成。

### 技术默认方案

以下细节是基于已确认方向采用的执行默认，允许根据兼容性验证调整，并在计划变更中登记依据；不把某个库误记为用户指定。

| 项目 | 默认选择与理由 |
|---|---|
| 工程组织 | 单仓库内 `apps/flowtrace/` 与 `server/` 两个独立工程，共用 `contracts/` 中的接口与业务样本，分别构建和发布 |
| 服务端 | FastAPI、SQLAlchemy、Alembic 与 PostgreSQL；先采用模块化单体，降低部署与排错成本 |
| 客户端存储 | Android/Windows 使用 SQLite，Web 单独适配浏览器持久化；统一领域与同步契约，先验证目标平台的存储插件能力 |
| 连接方式 | 客户端可配置流迹服务器地址；API 契约和兼容策略明确版本，服务端不依赖 Flutter 构建工具才能运行 |
| 使用模式 | 日常读写本地优先，联网同步；登录、邀请和管理等动作按联网语义处理 |
| 用户管理 | 账号密码与邀请注册；服务端从首版校验用户和账本权限，后台管理角色与账本成员角色分别定义 |
| 后台技术 | FastAPI 加 Jinja2 服务端页面，随 Python 服务端发布；Flutter Web 用于用户记账，后台提供独立管理入口 |
| 附件与任务 | 初期附件存文件目录；独立任务进程结合 PostgreSQL 作业记录处理重试和去重，不预设 Redis 等额外服务 |
| Linux 运维 | Python 虚拟环境、Uvicorn、systemd、Nginx/HTTPS，明确配置、迁移、日志、备份与恢复步骤 |

后台职责包括控制账户与服务运行状态，不能因持有后台角色就默认获得所有私人账本的业务读写权限。个人资产、共享账本、附件和导出数据的访问边界以架构分册为准。

### 平台与行为适配

Android 是产品体验的首个对照平台；后台管理页面在账号阶段出现，不代表用户 Web 客户端提前成为首发平台。用户 Web 和 Windows 分别安排完整页面、存储、交互、离线与同步验收。

P1 的 Linux 环境用于隔离工程演练，P2 的最小后台用于开发测试与个人自用。首次受控朋友试用须等 P5 中 A01 至 A07 基础后台能力全部就绪；首次面向用户的正式 Linux 交付在 P8 核验。

Android 无障碍、截图分享、小部件与后台执行需要平台接入；Web/Windows 根据真实系统能力提供对应入口。不能将代码复用率当作各端能力已完全一致，也不能用桌面浏览器截图替代 Windows 原生构建与验收。

金额、汇率、退款报销、账户变化和统计口径先形成带样本的契约，再分别实现。钱迹服务端冲突裁决等未知行为由流迹明确制定和测试，不能伪称已观察到原实现。原应用未实测流程使用隔离样本补齐证据，真实个人账目不作为试验数据。

### 可选改进与边界

iOS、macOS、Linux 桌面客户端不在本次已确认平台清单。开放公众注册、收费会员体系、第三方社交登录、对象存储、多节点高可用和完整监控平台可另行提出，不占用当前主线。钱迹会员功能涉及的产品能力继续保留，流迹是否收费不是复刻这些能力的前提。

2026-10-21 的规划任务未包含实现应用、创建真实用户、修改真实钱迹账单、生产发布、提交或推送；该段是历史规划边界。后续开发、本地恢复提交及当前生产包分别已获授权。Git 推送仍未授权，后续外部操作继续依具体授权执行。

每批由主代理选择依赖已满足、文件范围可分离的工作包，向子代理提供明确的任务编号、输入、必读契约、允许修改范围、步骤、验收命令和交接要求。主代理保留共享契约、迁移顺序和最终合并责任。

当前 Alpha 每批最多2个同时活动的子代理，每位只负责一个明确工作包；原规划阶段的三位分册作者是历史事实，不提高当前并发上限。任务分册给出完整长期任务的派发说明，共享模型、API 契约、生成代码与数据库迁移不能由多个代理无序修改；先由责任代理输出版本，再交给依赖任务实现。

实现代理交付后，由未承担相同实现的代理或主代理独立核验关键行为、权限和回归，再进入集成。子代理自述“完成”不等于验收证据；接收方核对真实文件与命令回执。未具备环境时如实记录补验条件，不把替身或文档检查算成平台通过。
