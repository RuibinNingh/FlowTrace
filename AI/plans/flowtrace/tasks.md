## P0：证据补齐与契约（4 个工作包）

### P0-01 固定全量对照与未实测流程

- **需求 / 角色 / 前置：**R01、R09，F01–F22；产品取证角色；无开发前置，先阅读现有调研和工作区说明。
- **输入与目标：**使用 `work/qianji-research/selected-ui-states.json` 的 S01–S56、现有截图/交付物、产品范围及用户原话；将“完全模仿”变成页面、操作、账务结果的逐项清单。
- **步骤：**定位每个状态的实际本地证据；重定位材料中的旧绝对路径；记录触发步骤、权限/登录前置、空态/错误态和退出路径；补齐报销提交、共享/同步等未实测分支；分别登记观测、静态线索、推断和设计默认，不用静态表单证明流程成功。
- **预期输出：**`AI/plans/flowtrace/evidence-matrix.md`、`contracts/fixtures/parity/` 中不含私人数据的对照描述、F01–F22 到证据/验收 ID 的索引；新增业务文档后同步导航。
- **并行边界：**只维护证据清单和脱敏样本，不修改业务模型；付费或不可进入页面保留事实缺口，向总协调者说明可采用的待验证行为规则，不自行删除该功能。

- **失败与回退：**材料缺失只阻塞对应精确对照；保持原件不变，记录新旧路径与缺失范围。涉及用户目标缩减时先提出明确差异，其余独立任务继续。

### P0-02 固定账务、权限与时间规则

- **需求 / 角色 / 前置：**R01、R04，F02、F07–F16、F18、F20；领域契约角色；依赖 P0-01 的已知行为，可先处理已取证部分。
- **输入与目标：**对照样本和架构建议；明确金额单位/范围、币种精度、汇率、账本月份起始日、时区、转账手续费、预算/统计独立标记及高级账务语义。
- **步骤：**为收入、支出、转账、还款、借入/借出、退款、报销、分期、周期与存钱定义状态转换和关联删除规则；区分个人资产所有权与账本成员权限；明确每类业务影响余额、收支、预算、资产的唯一位置；给出舍入、末期余数、月底/闰年、负债符号和跨币种例子。
- **预期输出：**`contracts/money-time.md`、`contracts/ledger-rules.md`、`contracts/permissions.md`、`contracts/fixtures/ledger/`；文件由契约角色独占编辑。
- **并行边界：**客户端和后端各自审阅同一套输入输出，不各立账务算法。未观测规则标为设计默认及后续核对点，由总协调者整合，不虚构钱迹行为。
- **验收：**样本能逐笔列出余额、收入、支出、预算占用和净资产期望值；退款/报销/分期不存在两条互相矛盾的统计口径；所有权、共享成员、系统管理员分别有允许/拒绝矩阵；范围外金额和缺失汇率的处理明确。
- **失败与回退：**规则冲突只暂停依赖该规则的实现；更新契约版本与受影响夹具清单，保留历史决定和理由，不先用浮点或静默覆盖临时凑通。

### P0-03 固定 API、同步、附件与作业契约

- **需求 / 角色 / 前置：**R02–R04、R08，F10、F15、F18、F20–F22；接口与同步契约角色；依赖 P0-02 的对象/权限边界。
- **输入与目标：**架构方案及权限矩阵；给 Flutter、Python、后台和任务 worker 提供可独立实现的共同契约。
- **步骤：**定义 `/api/v1`、错误结构、分页、字符串金额、设备/会话、operation_id 与请求摘要、base_revision、冲突对象、删除墓碑、全量重建和 epoch；同步游标采用事务内受 scope 锁保护的修订顺序；定义附件授权/校验及上传重试、occurrence 唯一键/租约/补跑、后台 Cookie/CSRF 与客户端凭据。先编写审阅用 OpenAPI 候选；P1-02 实现后从服务端模型导出并比对，固定唯一生成权威。
- **预期输出：**`contracts/openapi.json`、`contracts/sync-v1.md`、`contracts/attachments.md`、`contracts/jobs.md`、`contracts/fixtures/api/`、`contracts/fixtures/sync/`。
- **并行边界：**契约维护者独占接口定义；代理提变更提案后顺序合入。领域金额不走 JSON number；同步元数据和私人数据的授权范围均入契约。
- **验收：**接口样本包含成功、越权、冲突、回包丢失重试、相同操作 ID 不同正文、撤权及墓碑过期；两事务先分配/后提交的时序有明确无漏拉结论；合同夹具可供 P1/P2 直接实现，后台动作调用同一授权服务。
- **失败与回退：**破坏性变更更新版本并列迁移步骤；保留旧夹具用于兼容测试，不由单端先改变协议后要求另一端追赶。

## P1：基础工程与 Linux 隔离演练（4 个工作包）

### P1-01 Flutter 工程与跨端本地存储基础

- **需求 / 角色 / 前置：**R02、R05，F20；Flutter 基础设施角色；依赖 P0-03、P0-04。
- **输入与目标：**统一契约、UI 映射和平台预研；建立单一 Flutter 业务客户端，支持平台适配而非三套业务实现。
- **步骤：**创建 Android/Web/Windows 目标；分离领域、数据、展示和平台适配层；搭建路由、主题、错误处理和服务器地址配置；实现本地迁移、事务、设备分区、outbox 抽象；用最小样例提前验证 Web 持久化/多标签页与 Windows SQLite 插件可行性。
- **预期输出：**`apps/flowtrace/pubspec.yaml`、`pubspec.lock`、`lib/app/`、`lib/core/`、`lib/data/`、`lib/platform/`、`test/`，以及 `AI/modules/client.md`。
- **并行边界：**基础设施角色独占路由注册、依赖锁与数据库主入口；功能代理后续只改各自 `features/`。Web 原型只用于提前消除存储风险，正式 Web 交付仍在 P6。
- **验收：**静态分析通过；本地迁移从空库、旧测试库各执行成功，重启后样例和 outbox 保留；不存在硬编码生产地址/凭据；Android 最小应用能在记录身份的设备启动，其他缺失环境列补验。
- **失败与回退：**迁移前备份隔离数据库；插件不支持时更换适配层且保留同一领域接口；不清理用户实际数据库来使测试通过。

### P1-02 Python 独立工程与数据迁移基础

- **需求 / 角色 / 前置：**R03、R04、R06、R07，F20、F21；后端基础设施角色；依赖 P0-02、P0-03。
- **输入与目标：**Python/FastAPI、SQLAlchemy/Alembic、PostgreSQL 方案；可独立于 Flutter 安装、运行和测试的服务端。
- **步骤：**建立 Python 包和精确依赖锁；配置环境变量/示例配置、健康检查、数据库连接与最小迁移；建立认证/业务/同步/后台/worker 模块边界；实现关联 ID、结构化脱敏日志和统一错误返回；设置只连隔离数据库的测试入口；从服务端模型导出 OpenAPI，与 P0 候选比对并固定后续导出/兼容检查的唯一入口。
- **预期输出：**`server/pyproject.toml`、`requirements.lock`、`requirements-dev.lock`、`.env.example`、`src/flowtrace_server/`、`server/migrations/`、`server/alembic.ini`、`tests/`，以及 `AI/modules/server.md`；`contracts/openapi.json` 以后由服务端模型导出。
- **并行边界：**基础角色独占依赖、迁移链、应用入口和全局配置；业务代理不得各自引入 Docker、Redis/Celery 或另一数据库作为隐含依赖。
- **验收：**新虚拟环境按锁安装后能导入包、启动 API，健康检查反映数据库可用/不可用；迁移可建空测试库且重复执行无副作用；测试拒绝未标识的生产数据库；敏感凭据不出现在日志中。
- **失败与回退：**迁移失败保持原数据库状态并检查事务；只在隔离环境验证恢复路径。含数据变换的迁移不默认 `downgrade`，先选择前向修复或经过演练的快照恢复。

### P1-03 精确金额与账务参考实现
