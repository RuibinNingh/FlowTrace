### 1.1 用户已经确认的要求

| 要求 | 可验收的产品含义 |
| --- | --- |
| “叫做 流迹(FlowTrace)” | 对外名称为“流迹（FlowTrace）”，客户端和后台使用统一身份。 |

### 1.2 当前采用的默认设计

以下是为使计划可执行而采用的建议，不能倒写成用户逐项指定的细节。实现前由总计划记录更改，普通实现选择无需反复确认。

- 初期邀请注册；拥有者、可编辑成员、只读成员区分账本权限。多用户不意味着所有人共用同一个账本。
- 日常记账离线优先，先持久化到设备，再同步；账号管理、邀请、服务器管理需要联网。Web 首次打开和离线存储能力单独验证，不假定与 Android 完全相同。
- 同一账号跨设备访问；同一条记录的并发修改有可见的处理结果，重复请求不得重复记账。具体同步协议、撤权及设备清理规则由架构契约定义。
- 金额按币种精度精确计算；原金额、换算依据、手续费、退款和报销关联可以追溯。账务一致性优先于动画细节。
- 普通用户 Web 客户端与后台面板有独立入口和权限；后台管理身份默认不等于任何私人账本的成员。
- 自托管初期全功能可用。原应用会员状态是调研条件；商业付费、会员售卖、广告及对接钱迹官方账号不作为流迹初期依赖。
- Android UI 保留钱迹的导航、信息层级、选择器、编辑和返回行为；使用流迹名称与标识。截图中的设备字体和 720 × 1570 物理像素不直接作为通用尺寸。

以上默认设计所用框架和部署组件的具体取舍见架构文档，本文件不绑定第三方库版本。

## 6. 服务端后台面板

“后台面板”是服务器运营者使用的 Web 管理界面，与普通用户 Web 记账客户端分别验收。面板 UI 的实现技术由架构决定；不能仅以 API 文档页、命令行输出或数据库客户端代替后台。

P1 只做隔离工程与部署演练；P2 提供面向开发测试和个人自用的最小管理后台。首次朋友试用必须等待 A01–A07 全部就绪；P5 完成后台全量能力并验收，P8 再验证正式 Linux 交付。早期工程演练和自用版本不应被标记为朋友试用或正式对外交付。

### 6.2 后台与普通账本的权限关系

| 身份 | 可以做 | 默认不可以做 |
| --- | --- | --- |
| 普通用户 | 管理自己的账号和授权账本，查看自己的设备/同步状态。 | 进入后台、查看其他用户的私人数据、修改系统配置。 |
| 账本所有者 | 邀请/移除本账本成员、设角色、管理本账本设置与内容。 | 查看成员其他账本、私人账户余额/资产总览，授予后台角色。 |
| 可编辑成员 | 根据最终权限矩阵录入/维护共享账本允许的记录。 | 自动获得所有者专属管理权或其他成员私人资产。 |
| 只读成员 | 查看被授权账本、允许的统计和附件。 | 新建、修改、删除、导入、改变成员或设置。 |
| 后台管理员 | 用户、邀请、配置、任务与脱敏诊断等运维管理。 | 仅因后台角色而查询或更改任何私人账单、下载私人附件、伪装用户记账。 |
| 服务器所有者/恢复管理员 | 经审计执行完整备份和恢复等高权限操作。 | 向普通后台管理员隐式开放全部备份下载权限。 |

服务端必须逐请求校验账本成员与操作权限，前端隐藏按钮不能替代权限检查。共享账本中账户归属和余额变更由明确授权约束，不能允许成员把记录绑定到无权操作的他人资产。

以上是应用权限边界。拥有服务器数据库/磁盘权限的部署者、可读取全量备份的恢复管理员仍可能接触原始数据；当前不包含端到端加密承诺。若以后要求服务器运营者也不可读取账务，需要另行设计加密与共享模型，不能只靠后台隐藏列实现。

## 9. 范围完成与变更原则

- 早期“能记账”、首个 Android 包、后端首次启动、基础后台上线均为阶段产物，不等于完整应用完成。F01–F22 与适用平台的验收须在总任务清单中有归属。
- Android 的系统集成能力与其他平台的替代入口分别验收；隐藏不适用系统权限入口不算删去通用记账、识别草稿和数据管理能力。
- 所有未知账务规则在实施前形成可运行黄金样本或明确的流迹默认契约；用户要求变更与额外增强分别记录，不以技术困难静默缩减范围。
- 本轮只完成规划文档；应用代码、设备验证、账务测试、后台浏览器主路径、Linux 部署、备份恢复均留给后续获准实施的任务。
