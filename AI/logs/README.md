# 维护任务日志约定

本目录记录仓库持久化改动的背景、行为变化与验证事实。协作入口见 [AGENTS.md](../../AGENTS.md)，当前系统行为见相应模块文档。

## 文件与任务身份

文件名使用 `YYYY-MM-DD_topic.md`，日期采用 `Asia/Shanghai`，主题由小写英文、数字与连字符组成。文件标题以相同日期开头，任务标识与文件名主题一致。不同任务使用不同主题；重名时加 `-2` 等后缀。

标题后使用任务状态块，例如：

```markdown
> **任务**
> - 标识：example-task
> - 状态：进行中
```

任务正文保留五节，每节填写具体事实；没有相关项目时写“无”并说明必要边界：

1. `## 背景`：用户原话、目标、实际基线、执行环境和关联计划。
2. `## 行为变化`：用户或调用方可观察的变化。
3. `## 影响文件`：本任务实际涉及的文件与原因。
4. `## 已执行验证`：真正执行的命令、结果与证据，保留失败及重跑事实。
5. `## 未执行验证`：未运行的检查、原因及需要的补验条件。

使用 [任务日志模板](../../.agents/skills/repo-collaboration-logging/assets/templates/task-log.md) 起草时，替换全部占位符，并按实际情况删除仅供补丁交接使用的章节。

## 生命周期与历史保护

- 同一个进行中任务跨轮续作，继续更新同一文件；约定范围完成后改为“已交付”。
- 已交付或没有状态块的旧记录保留原文，不覆盖、删除或改名。新任务另建日志，并引用相关旧记录。
- 修正历史错误时，只在原文末尾追加 `## 勘误（YYYY-MM-DD）`，写明原结论、修正结论和依据，并在本次任务记录中说明。
- “已交付”仅代表该任务约定范围完成，提交、推送、部署与各环境验证分别记录。

当前没有自动历史保护门禁，交付时人工对照本次基线核对。只读答疑或仅在仓库外生成交付物，不新增仓库任务记录。这里不收纳运行日志、凭据或原始业务数据。
